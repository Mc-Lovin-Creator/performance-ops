# Performance Ops

**We keep punching above our weight.**

> **Deploying to Emergent?** Start at [`EMERGENT_START.md`](EMERGENT_START.md). Every prompt to paste is in [`deploy/PASTE.md`](deploy/PASTE.md).

Private clinical and performance platform for the Abu Dhabi performance lab: Player 1 first, then the squad, the team and the facility.
Every test, prescription and teaching card carries its source and an evidence grade.

## What is in here

| Folder | What it is |
| --- | --- |
| `app/src/` | The app: one page, plain JavaScript modules joined in a fixed order by `app/build.py`. `anatomy2.js` is the 3D engine (three.js). |
| `app/assets/` | The anatomy model (Z-Anatomy on BodyParts3D, CC BY-SA) and the vessels/nerves pack, packed for the browser. |
| `backend/` | API: sign-in, roles, Player 1 access, encrypted clinical fields, audit log, booking clash checks, wearable sync (Oura, WHOOP, Polar, Garmin, Apple Health; see `docs/WEARABLES.md`). Python, ASGI (Starlette), MongoDB. |
| `frontend/` | Thin React (CRA + craco) host so Emergent can run it like its other apps. `public/index.html` is generated by the build. |
| `tests/` | Static checks (evidence links, data classification, secrets, syntax) and a browser smoke test of every page. |
| `tools/anatomy-pipeline/` | How the anatomy pack was made from the Z-Anatomy atlas (reproducible, not needed to run the app). |
| `deploy/` | Staged deployment to Emergent: guides, paste-in prompts, status tracker. `scripts/` has the key maker, first-account and stage check scripts. |
| `deploy/` | Staged deployment to Emergent: [stage guides](deploy/README.md), [paste-in prompts](deploy/PASTE.md), [agent rules](deploy/EMERGENT_RULES.md), [change loop](deploy/CHANGES.md), [status tracker](deploy/STATUS.md). |
| `scripts/` | `gen_keys.py` (server keys), `first_lead.py` (first account), `check_deploy.py` (checks each stage). Standard library only; run on your computer. |
| `docs/` | Emergent hand-off, security model, evidence policy, licences, UAE hosting checklist, wearable sync set-up, 90-day plan. |

## Run it

```bash
python3 app/build.py                 # builds dist/performance-lab.html (demo) and frontend/public/index.html (production)
# demo, no server: open dist/performance-lab.html
# production:
cd backend && cp .env.example .env    # then fill JWT_SECRET and FIELD_KEY:  python -m core.admin gen-key
uvicorn server:app --host 0.0.0.0 --port 8001
python -m core.admin create-user jp@example.com lead jp --p1     # password is typed at a hidden prompt
cd ../frontend && yarn install && yarn start                      # REACT_APP_BACKEND_URL in frontend/.env
```

## Tests

```bash
npm install && npx playwright install chromium
npm test     # build + static checks + every page in a browser + backend API tests
```

## Rules this code keeps

- Player 1 data is readable only by users flagged for Player 1 who are clinicians (lead, physio, physician). Nothing is pushed to Player 1 unless a clinician shows it.
- Clinical values are encrypted at rest; every clinical read and every write is in the audit log.
- No passwords, codes or keys live in the repo. Accounts are created with the admin command; passwords are typed, never passed as arguments.
- Real patient or staff exports (CSV, spreadsheets, photos) are not committed (`.gitignore`).
- AI prompts never contain names or patient details: the Ask page blocks them before sending.
- Wearable tokens stay on the server, encrypted; nothing connects without recorded consent; only daily summaries are kept.
- Hosting for real patient data must meet Abu Dhabi DoH requirements (ADHICS) before go-live; see `docs/SECURITY.md`.
